The quiche example server’s default listening address is `0.0.0.0:4433` (see the `SERVER_USAGE` constant in `apps/src/bin/quiche-server.rs`). This port is free to use on the experimental network. If a different port is desired, it can be overridden with the `--listen` flag.

## Verified server command (to be run **after** the experimental interface is up)

```bash
# From the repository root
cd /home/rosa/experiments/quicscope-novelty/pacing-host-delay/source/quiche

# Build the binary if not already built (see reports/QUICHE-BUILD.md)
cargo build -p quiche_apps --release

# Create a directory for qlog output (ensure it is writable)
mkdir -p /tmp/qlog_sender

# Set the environment variable so quiche writes qlog files
export QLOGDIR=/tmp/qlog_sender

# Run the server – it will bind to all interfaces (including the experimental one)
target/release/quiche-server \
    --listen 0.0.0.0:4433 \
    --cert apps/src/bin/cert.crt \
    --key apps/src/bin/cert.key \
    --qlog-dir $QLOGDIR
```

**Explanation of flags**

- `--listen <addr:port>` – address and port the server should bind to. `0.0.0.0` means “all interfaces”.
- `--cert` / `--key` – paths to a self‑signed certificate/key pair shipped with the repository (`apps/src/bin/cert.crt` and `cert.key`).
- `--qlog-dir` – directory where the server will write qlog files (each connection creates a separate file). The flag is optional because the code also respects the `QLOGDIR` environment variable; we set it explicitly for clarity.
